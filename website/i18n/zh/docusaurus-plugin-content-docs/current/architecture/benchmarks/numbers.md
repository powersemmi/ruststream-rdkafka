# 数字

`ruststream-rdkafka` 的基准测试数字测的是什么，以及不能从中得出哪些结论。

## 与裸客户端的对照 {/* #the-comparison-against-a-raw-client */}

同一行中的三个循环可以互相比较，因为它们在同一个进程中、交替地、对着同一个 Broker 运行。一行不能与另一个 Broker crate 公布的行比较：各种传输在每条消息上做的工作不同。

Broker 运行在同一台机器上，走回环接口。没有网络延迟，同样的每条消息开销在时间中所占的比例，比面对跨网络的集群时更大。应把该百分比读作已部署服务所付代价的上界。

`受 Broker 限制` 的行表示裸客户端在运行的大部分时间里都在等套接字。本 crate 和运行时的工作于是发生在这段等待之内，测出的差异接近零。这是开销的下界，而不是对它的测量。

## 代码的开销 {/* #the-cost-of-the-code */}

指令计数包含本 crate 的代码、它上面的运行时，以及在服务线程上发起的 librdkafka 调用。由于 Broker 是真实的，它在各次运行之间会有少许变动。同样的计数在缓存未命中处要花更多时间，因此计数不等于时间。

每个数字都是稳态，即 1000 次投递的运行与 2000 次投递的运行之差。启动服务、加入组以及它们背后的首批内存分配属于冷启动，只付一次。

## 它们不意味着什么 {/* #what-they-do-not-mean */}

一行就是一个消费者读取一个只有一个分区的主题，消息体很小，集群只有一个节点。它测量的是一次投递在本 crate 内部的开销，而不是 Kafka 能承载多少。

多分区的主题、一组工作分区和[事务流水线](../../components/transactions/exactly-once/index.md)各自回答不同的问题，这个对照不测量其中任何一个。代码图在同一测试环境上统计[批处理器](../../components/subscriptions/batches.md)和应答。

这些数字是一台机器在某一天的快照，构建信息记录在旁边。它们在一台只做这次运行的机器上手动重新测量：它们显示的差异小于共享机器的噪声。
