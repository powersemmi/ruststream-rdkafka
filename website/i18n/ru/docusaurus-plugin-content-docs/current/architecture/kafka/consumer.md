# Консьюмер

Консьюмер librdkafka выбирает записи заранее в собственных потоках, выдаёт их по одной за опрос и
фиксирует сохранённое смещение по таймеру.

<Diagram name="consumer" words={words} />

librdkafka выбирает записи назначенных партиций в локальную очередь до того, как приложение их
попросит. Размер этой очереди ограничивает `queued.max.messages.kbytes` (64 МиБ). Когда очередь
полна, выборка для партиции приостанавливается на `fetch.queue.backoff.ms` (одна секунда).

Опрос снимает с очереди следующую запись.
[`StreamConsumer`](https://docs.rs/rdkafka/0.39.0/rdkafka/consumer/stream_consumer/struct.StreamConsumer.html)
из rust-rdkafka делает это через `recv`, асинхронный вызов, который можно безопасно отменить.

Хранилище смещений - это позиция в памяти для каждой партиции. По умолчанию
(`enable.auto.offset.store`) опрос сохраняет смещение записи, которую выдаёт, ещё до того, как
приложение её обработало. Пунктирная стрелка показывает другой путь: приложение выключает
автоматическое сохранение и сохраняет смещение, когда запись обработана.

Пока включён `enable.auto.commit`, таймер фиксирует сохранённые позиции каждые
`auto.commit.interval.ms` (пять секунд) и ещё раз при закрытии консьюмера. При падении теряется
то, что было обработано после последней фиксации, и это читается заново. При сохранении по
умолчанию запись, сохранённая при выдаче и ещё не обработанная, после падения пропускается.

Поведение и значения по умолчанию взяты из librdkafka
([управление смещениями](https://github.com/confluentinc/librdkafka/blob/v2.12.1/INTRODUCTION.md#offset-management),
[конфигурация](https://github.com/confluentinc/librdkafka/blob/v2.12.1/CONFIGURATION.md)).
