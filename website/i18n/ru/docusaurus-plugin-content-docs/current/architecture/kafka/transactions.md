# Транзакции Kafka

Транзакция Kafka делает записи в нескольких партициях и прочитанные смещения видимыми вместе или не
делает видимым ничего.

<Diagram name="transactions" words={words} />

[Транзакционного продюсера](../../components/transactions/index.md) называет его `transactional.id`. Он ведёт по одной транзакции за раз.
Записи, отправленные внутри неё, попадают в журнал сразу, а фиксация пишет маркеры, которые делают
их видимыми.

Читатель с уровнем изоляции `read_committed`, который в librdkafka стоит по умолчанию, видит
записи транзакции только после фиксации и никогда после прерывания. Читатель с уровнем
`read_uncommitted` видит их по мере записи.

Прочитанные смещения могут войти в транзакцию. Тогда входные позиции сдвигаются ровно в тот
момент, когда результат становится видимым. Это схема [«прочитать, преобразовать, записать»](../../components/transactions/exactly-once/index.md) из
[KIP-447](https://cwiki.apache.org/confluence/display/KAFKA/KIP-447%3A+Producer+scalability+for+exactly+once+semantics).
Прерывание оставляет смещения на месте, поэтому вход читается заново, уже в новую транзакцию.

Транзакцию, открытую дольше `transaction.timeout.ms` (одна минута), прерывает координатор.
Продюсер, запущенный с уже занятым id, отсекает прежний: следующий вызов того продюсера
завершается ошибкой.

Значения по умолчанию и правило отсечения взяты из librdkafka
([транзакционный продюсер](https://github.com/confluentinc/librdkafka/blob/v2.12.1/INTRODUCTION.md#transactional-producer),
[конфигурация](https://github.com/confluentinc/librdkafka/blob/v2.12.1/CONFIGURATION.md)).
