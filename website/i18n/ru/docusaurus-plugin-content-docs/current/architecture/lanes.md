# Партиции воркеров

Одна подписка читает все свои партиции через один консьюмер, а `workers(n, by_key)` раскладывает
записи по партициям воркеров, выбирая их по партиции записи.

<Diagram name="lanes" words={words} />

Поток подписки выдаёт по одной записи, из какой бы партиции она ни пришла. Без `workers` один цикл
вызывает обработчик для каждой записи по очереди, поэтому каждая партиция сохраняет порядок, и
ничего не выполняется параллельно.

`workers(n, by_key)` запускает `n` партиций воркеров. Запись попадает в ту партицию воркеров, на
которую указывает хеш её ключа, а партиция воркеров выполняет свои записи по порядку. По умолчанию
ключ - партиция записи ([`LaneKey::Partition`](api:ruststream_rdkafka::LaneKey::Partition)),
поэтому партиция Kafka никогда не делится между двумя партициями воркеров, и порядок Kafka
сохраняется. Если партиций воркеров меньше, чем партиций, каждая из них обслуживает несколько
партиций.

[`LaneKey::RecordKey`](api:ruststream_rdkafka::LaneKey::RecordKey) вместо этого выбирает партицию
воркеров по ключу записи. Записи одного ключа сохраняют порядок, а разные ключи одной партиции
выполняются параллельно. У записи без ключа нет ключа партиционирования, и такие записи по кругу
расходятся по партициям воркеров.

Подтверждения из параллельных партиций воркеров приходят не по порядку. При `Commit::Tracked`
зафиксированное смещение всё равно никогда не обгоняет запись, которая не завершилась, как
показывает страница [Завершение](settlement.md).

Обработчик пакетов берёт одну запись и всё, что librdkafka уже выбрала, до размера, заданного при
монтировании, поэтому пакет часто меньше этого размера.
