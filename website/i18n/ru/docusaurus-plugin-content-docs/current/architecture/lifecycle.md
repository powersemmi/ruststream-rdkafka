# Жизненный цикл

[`KafkaBroker::new`](../components/broker/index.md) записывает конфигурацию, connect
проверяет кластер, старт открывает консьюмер на каждую подписку, а завершение работы отправляет
то, что осталось в очереди.

<Diagram name="lifecycle" words={words} />

`new` не выполняет ввода-вывода, поэтому сборщик сервиса остаётся синхронным. Рантайм подключает
брокер при старте приложения. Подключение запрашивает метаданные кластера через временный клиент,
собранный из настроек продюсера, в пределах
[`connect_timeout`](../components/broker/startup.md) (30 секунд). Старт
прерывается, если кластер недоступен или librdkafka отвергает свойство продюсера.

[Дескриптор](../components/subscriptions/index.md) каждой подписки разрешается один раз, по подключённому брокеру. Подписка с группой
открывает свой консьюмер и ждёт, пока группа назначит ему партиции и станет известно начало каждой
из них. Ожидание ограничено
[`assignment_timeout`](api:ruststream_rdkafka::KafkaBroker::assignment_timeout) (одна минута).
Пока рантайм не начал чтение, консьюмер продолжает отвечать группе, поэтому перебалансировка его
не ждёт. Подписка, которая не называет группу, под брокером без
[`default_group`](api:ruststream_rdkafka::KafkaBroker::default_group) прерывает старт.

Сервис, который только читает, продюсер не запускает. Общий продюсер открывает первая публикация.

Завершение работы помечает соединение закрытым, а затем в пределах
[`flush_timeout`](../components/broker/shutdown.md) (30 секунд) отправляет то,
что ещё держит продюсер. [`ClosedKafkaBroker`](api:ruststream_rdkafka::ClosedKafkaBroker)
сообщает о записях, которые остались неотправленными. Консьюмер закрывается, когда удаляется его
подписка: он выходит из группы, а если подписка не транзакционная, по пути фиксирует сохранённую
позицию.
