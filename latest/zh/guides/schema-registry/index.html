    Schema Registry：Avro 与 JSON Schema

    本指南在 Confluent 信封下读写 Avro 和 JSON Schema 记录，每个 schema 都在启动时与 Schema Registry 核对。

    由注册中心支持的记录以 Confluent 信封开头：一个零字节，然后是写入它所用 schema 的四字节 id。 schema 本身保存在注册中心里。 在 RustStream 中，schema 属于编解码器，所以处理器接收和返回的都是普通的 serde 结构体。

    Cargo.toml
    [dependencies]
    ruststream-rdkafka = { version = "0.7", features = ["avro"] }
    apache-avro = { version = "0.22", features = ["derive"] }

    avro feature 在 schema-registry 之上加入 Avro 编解码器，后者带来注册中心客户端和信封。 apache-avro 提供 AvroSchema derive；使用本 crate 所依赖的版本。

    模型​

    src/main.rs
    #[derive(Debug, Clone, PartialEq, Serialize, Deserialize, AvroSchema)]
    struct Invoice {
        id: i64,
        amount_cents: i64,
        // Added in the second version of the schema; older producers do not write it.
        #[avro(default = r#""EUR""#)]
        currency: String,
    }

    #[derive(Debug, Clone, PartialEq, Serialize, Deserialize, AvroSchema, Outgoing)]
    #[outgoing(name = "receipts")]
    struct Receipt {
        invoice: i64,
        amount_cents: i64,
        currency: String,
    }
    src/main.rs
    #[derive(Debug, Clone, PartialEq, Serialize, Deserialize, AvroSchema, JsonSchema)]
    struct Invoice {
        id: i64,
        amount_cents: i64,
        // Added in the second version of the schema; older producers do not write it.
        #[avro(default = r#""EUR""#)]
        currency: String,
    }

    #[derive(Debug, Clone, PartialEq, Serialize, Deserialize, AvroSchema, JsonSchema)]
    struct Receipt {
        invoice: i64,
        amount_cents: i64,
        currency: String,
    }

    // What `#[derive(Outgoing)]` with `#[outgoing(name = "receipts")]` writes.
    impl OutgoingDestination for Receipt {
        type Form = FixedName;

        const DESTINATION: &'static str = "receipts";
    }

    impl MessageHeaders for Receipt {
        type Contract = NoHeaders;
    }

    impl MessageInfo for Receipt {
        const NAME: &'static str = "Receipt";
        const DESCRIPTION: Option<&'static str> = None;
    }

    AvroSchema 推导出每个结构体的 Avro schema。 currency 是在发票 schema 的第二个版本中加入的。 #[avro(default)] 是不含该字段的记录读出时所取的值。

    issue_receipt 读取一张发票，并在 receipts 主题上以一张收据作为回复。 其中没有任何代码知道 Avro 或信封的存在。

    注册中心、预取与编解码器​

    • 宏
    • 手写
    src/main.rs
    fn service(broker: KafkaBroker, registry: SchemaRegistry) -> impl App {
        let prefetch = SchemaPrefetch::new(registry);
        let avro = AvroCodec::registry(&prefetch)
            .register::<Receipt>("receipts-value")
            .resolve_onto(Invoice::get_schema())
            .expect("a registry codec resolves its reader schema on the first delivery");
        let json = SchemaFramed::new(&prefetch, JsonCodec);

        RustStream::new(AppInfo::new("billing", "0.1.0")).with_broker_codec(
            broker.schema_prefetch(prefetch),
            avro.clone(),
            |b| {
                b.include(issue_receipt)
                    .out_reply(KafkaPublish::default())
                    .codec(avro);
                b.include_router(Router::new().with_codec(json).include(open_dispute));
            },
        )
    }

    #[ruststream::app]
    fn app() -> impl App {
        service(
            KafkaBroker::new(["localhost:9092"]).default_group("billing-svc"),
            SchemaRegistry::new("http://localhost:8081"),
        )
    }
    src/main.rs
    fn service(broker: KafkaBroker, registry: SchemaRegistry) -> impl App {
        let prefetch = SchemaPrefetch::new(registry);
        let avro = AvroCodec::registry(&prefetch)
            .register::<Receipt>("receipts-value")
            .resolve_onto(Invoice::get_schema())
            .expect("a registry codec resolves its reader schema on the first delivery");
        let json = SchemaFramed::new(&prefetch, JsonCodec);

        RustStream::new(AppInfo::new("billing", "0.1.0")).with_broker_codec(
            broker.schema_prefetch(prefetch),
            avro.clone(),
            |b| {
                b.include(subscriber("invoices", IssueReceipt).reply().build())
                    .out_reply(KafkaPublish::default())
                    .codec(avro);
                b.include_router(
                    Router::new()
                        .with_codec(json)
                        .include(subscriber("disputes", OpenDispute).build()),
                );
            },
        )
    }

    fn app() -> impl App {
        service(
            KafkaBroker::new(["localhost:9092"]).default_group("billing-svc"),
            SchemaRegistry::new("http://localhost:8081"),
        )
    }

    fn main() -> ExitCode {
        run_main(app)
    }

    SchemaRegistry::new 记录注册中心的 URL，此时还不发送任何请求。 它的每个克隆共用一个缓存，所以每个进程对一个 schema 只获取一次。 SchemaPrefetch 负责网络工作，schema_prefetch 把它挂到 Broker 上。 Broker 连接时，预取解析编解码器发布时所用的每个 subject。 记录到达时，它在编解码器运行之前获取信封所指的写入方 schema。 所以编解码器本身从不等待网络。

    AvroCodec::registry 基于预取构建 Avro 编解码器。 register 指定某个类型的值加帧时所用的 subject：收据以 receipts-value 发出。 解码不需要注册，因为每条记录都指出了自己的写入方 schema。

    with_broker_codec 用 Avro 编解码器解码作用域中的每个处理器。 回复用其挂载点上指定的编解码器编码，没有指定时用默认的 JSON 编解码器。 所以 out_reply(KafkaPublish::default()).codec(avro) 为收据指定 Avro 编解码器。

    读取较旧的写入方 schema​

    resolve_onto 让 Avro 把每条记录解析到读取方 schema 上，这里是 Invoice::get_schema()。 在 schema 第一个版本下写入的记录没有 currency。 解析时用该字段的默认值填充它，所以处理器读到的是 "EUR"。 读取方 schema 作用于其编解码器解码的每条记录，所以一个带读取方 schema 的编解码器只服务于一个类型。 有自己读取方 schema 的第二个类型，要在自己的路由器中使用自己的编解码器。

    注册 subject 与缺失的 subject​

    服务本身不注册 schema：由拥有主题的一方注册它的 subject，比如在部署步骤中。 register_avro 把某个类型的 Avro schema 注册到一个 subject 下，register_json 注册它的 JSON Schema，register 注册以文本给出的 schema。

    当编解码器发布时所用的 subject 不在注册中心里时，Broker 不会连接，错误信息会指出这个 subject。 MissingSubject 选择改为怎样处理：

    策略行为
    Refuse （默认）服务不启动
    AutoRegister把该类型自己的 schema 注册到这个 subject 下，并记录一条警告
    PublishUnframed发布不带信封的裸数据，并记录一条警告

    在基于预取构建编解码器之前，用 on_missing_subject 设置它。

    启动时的兼容性检查​

    连接时，每个已注册类型的 schema 都按注册它时的方式接受检查。 subject 的兼容性级别决定与哪些版本比较：最新版本，或者在 _TRANSITIVE 级别下的每个版本。 与 subject 不一致的模型会让服务停止，错误中附有注册中心对差异的说明。 check_compatibility(false) 关闭这项检查，用于级别为 NONE 的 subject。

    信封下的 JSON Schema​

    • 宏
    • 手写
    src/main.rs
    #[derive(Debug, Clone, PartialEq, Serialize, Deserialize, JsonSchema)]
    struct Dispute {
        invoice: i64,
        reason: String,
    }

    #[subscriber("disputes")]
    async fn open_dispute(dispute: &Dispute) -> HandlerOutcome {
        if dispute.reason.is_empty() {
            tracing::warn!(dispute.invoice, "dispute without a reason dropped");
            return HandlerOutcome::drop();
        }
        tracing::info!(dispute.invoice, dispute.reason, "dispute opened");
        HandlerOutcome::ack()
    }
    src/main.rs
    #[derive(Debug, Clone, PartialEq, Serialize, Deserialize, JsonSchema)]
    struct Dispute {
        invoice: i64,
        reason: String,
    }

    struct OpenDispute;

    impl Handle<Dispute> for OpenDispute {
        fn handle(
            &self,
            dispute: &Dispute,
            _outs: &(),
            _ctx: &mut Context<'_>,
        ) -> impl Future<Output = Result<(), HandlerOutcome>> {
            if dispute.reason.is_empty() {
                tracing::warn!(dispute.invoice, "dispute without a reason dropped");
                return ready(Err(HandlerOutcome::drop()));
            }
            tracing::info!(dispute.invoice, dispute.reason, "dispute opened");
            ready(Ok(()))
        }
    }

    SchemaFramed 把核心的 JSON 编解码器包裹在信封中。 解码时跳过信封，读取其中的 JSON 文档。 编码时，用 register 为该类型指定的 subject 的 id 给值加帧，与 Avro 相同。 在上面的服务中，一个路由器把这个编解码器交给 disputes 订阅，因为最具体的编解码器优先。 JsonSchema 推导出类型的 JSON Schema，由 register_json 注册。

    AvroCodec::local 持有一个 schema，并对每条记录都使用它。 主题承载裸 Avro 数据：路径上没有信封、没有注册中心，也没有网络。 因此这个归档服务不需要注册中心就能运行和测试。

    转码路径​

    服务也可以让普通的 serde 模型保持使用默认的 JSON 编解码器，在 Broker 的边界上做转换。 KafkaBroker::schema_registry 在编解码器运行之前，把每次带帧的投递转换成 JSON。 SchemaFrame 通过 RustStream::publish_layer 添加，它按目的 subject 所保存的格式给每个发出的 JSON 载荷加帧：Avro、JSON Schema 或 Protobuf。 注册中心中没有 subject 的主题，按原样发布。 这条路径每条消息要做一次 JSON 转换，并且不会把记录解析到读取方 schema 上。 一个 Broker 只用其中一条路径：挂上 schema_registry 之后，交给编解码器的会是 JSON。

    接入其他注册中心 crate​

    SchemaRegistry::with_client 接收你自己的 RegistryClient，比如基于另一个 HTTP 栈或另一个客户端 crate 的实现。 之后，编解码器、预取和转码路径都通过它访问注册中心。

    自己完成全部 schema 工作的 crate，比如 schema_registry_converter，则改为在字节上工作。 处理器通过一个 #[derive(Deserialized)] 类型接收记录的字节，并通过一个 #[derive(Serialized)] 类型返回编码后的回复。 那个 crate 与 RustStream 之间只传递字节，所以它自己的 apache-avro 版本不必与本 crate 一致。
